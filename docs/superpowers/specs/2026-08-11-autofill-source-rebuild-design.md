# Autofill 源码重建设计

## 目标

从现有 `dist` 产物和设置页截图重建可维护、可测试、可发布的 Chrome/Edge Manifest V3 扩展源码。首版只还原现有智能测试数据填充能力，不实现结构化数据导入、规则库、自动提交或完整 Browser Agent。

## 产品边界

- 中文产品名为“智填”，英文产品名为“Autofill”，包代号为 `axiom-autofill`
- 浏览器语言为中文时显示中文界面，其余语言显示英文界面
- 用户在当前站点主动授权后才注入可拖动悬浮球；不会默认读取所有网站
- AI 只生成结构化字段值，程序负责确定性写入 DOM；扩展不点击提交、删除、支付、审批或发布按钮
- 页面已有输入值、密码、文件、隐藏字段和 URL 查询参数不得发送给模型
- API Key 仅保存在 `chrome.storage.local`，请求只发往用户配置并授权的模型地址

## 架构

采用 TypeScript、Vite、原生 DOM 和 Manifest V3。源码按职责拆分为共享类型与存储、模型协议适配、表单扫描、动作执行、悬浮球、后台消息处理、弹窗和设置页。业务逻辑保持无浏览器依赖或通过小型适配层隔离，以便 Vitest 在 jsdom 中测试。

模型配置显式记录 `protocol: "openai" | "anthropic"`。OpenAI 兼容接口使用 Chat Completions；Anthropic 兼容接口使用 Messages。旧配置没有 `protocol` 时，`apihub.agnes-ai.com` 迁移为 Anthropic，其余默认为 OpenAI。

## 核心流程

1. 用户在弹窗中为当前站点启用智填，扩展请求当前源站权限并注入内容脚本
2. 内容脚本创建 Shadow DOM 悬浮球并保存该源站启用状态与悬浮位置
3. 用户点击悬浮球后扫描可见、可编辑且非敏感字段，生成稳定的临时字段 ID
4. 后台读取默认模型，裁剪页面上下文并调用对应协议适配器
5. 后台校验模型返回对象，只保留扫描字段中允许的值类型，返回结构化执行计划
6. 内容脚本按控件类型写值并派发 `input`/`change` 事件，只显示填充数量，不提交表单

## UI 与数据

- 设置页复刻截图的双栏结构，增加“接口协议”选择；支持新增、编辑、启用、删除、显示/隐藏 API Key
- 弹窗显示当前站点启用状态、当前模型和设置入口；开关只影响当前站点
- 存储键延续 `smartFormFill.*` 前缀以兼容现有产物，并新增站点授权状态与 schema 版本
- 设置页保存模型时校验 HTTPS；仅 localhost/127.0.0.1/[::1] 允许 HTTP，并在用户手势内请求精确源站权限

## 错误与安全

- 模型请求 30 秒超时；同一标签页 3 秒内禁止重复请求
- OpenAI 接口在 `response_format` 返回 HTTP 400 时回退普通 JSON 提示
- 无字段、无模型、配置不完整、权限拒绝、网络失败、非 JSON 响应和不可匹配选项均返回中英文本地化状态
- 单选框按同名组和值匹配，不允许一个布尔值把整组单选框全部选中
- 内容脚本使用 Shadow DOM 隔离样式；卸载时移除监听器和节点

## 发布与验收

- 生成 16/32/48/128 px 图标、双语清单、README、隐私政策和 Chrome/Edge 商店文案
- 构建产物仅包含商店需要的文件，不包含 `.DS_Store`、源码映射和密钥
- 单元测试覆盖存储迁移、URL/权限、协议请求、响应解析、字段扫描、字段执行和单选框回归
- 集成测试覆盖设置 CRUD、站点开关、消息链路和不自动提交；构建后校验 Manifest 与引用文件完整性
